## Простыми словами

Почти любой сайт собран из одних и тех же деталей: поиск, фильтры, таблица, сортировка, страницы «1 2 3 … Вперёд», выпадающие списки, выбор даты, загрузка файла, всплывающее окно, уведомление «Сохранено», вопрос «Точно удалить?». Интернет-магазин, банк, CRM, TaskFlow — детали одни и те же, меняется только содержимое.

А раз детали одинаковые — **одинаковые и баги**. Сортировка, которая сортирует только текущую страницу. Фильтр, который сбрасывается после F5. Экспорт в CSV, который в Excel открывается «кракозябрами». Окно, которое закрылось от случайного клика мимо и унесло заполненную форму. Это не редкие баги одного проекта — они встречаются снова и снова.

Поэтому опытный тестировщик не придумывает проверки для каждого элемента с нуля. У него есть **готовый чек-лист на каждый типовой элемент**: увидел в задаче «добавить фильтр по статусу» — открыл чек-лист фильтра и прошёл.

Зачем это на работе:

- **Экономит время.** Не нужно каждый раз вспоминать, что бывает с пагинацией. Открыл, вычеркнул лишнее, прошёл.
- **Ловит то, о чём забывают.** Разработчик проверил, что фильтр фильтрует. А что будет, если включить два фильтра и нажать «Назад»? Чек-лист помнит за тебя.
- **Помогает на собеседовании.** «Как протестируете поиск?» — один из самых частых вопросов. С чек-листом в голове ответ получается структурным, а не «ну, введу что-нибудь».

В этом уроке:

- **таблица-оглавление** — главный риск каждого элемента;
- **чек-листы** на 14 элементов: что это, что проверять, типичные баги, лайфхак;
- **лайфхаки**: папка тестовых файлов, большой файл одной командой, много данных для пагинации за минуту;
- **как работать на задаче — по шагам**;
- какие элементы есть в веб-клиенте TaskFlow и где ещё потренироваться.

Многое из урока ты уже знаешь по частям: вёрстку длинного текста — из [урока 3](/web/03-verstka-i-maket), состояния «загрузка / пусто / ошибка» — из [урока 4](/web/04-sostoyaniya-interfeysa), проверку полей ввода — из [урока 5](/web/05-formy-i-validaciya). Здесь мы не повторяем это, а собираем в готовые списки по элементам.

## Оглавление: элемент → главный риск

| Элемент | Главный риск — проверь первым |
|---|---|
| **Поиск** | Не находит то, что есть: регистр, пробелы, часть слова |
| **Фильтры** | Комбинация фильтров даёт неверный результат или «теряется» |
| **Сортировка** | Сортирует только текущую страницу, а не все данные |
| **Пагинация** | Дубли и пропуски между страницами |
| **«Показать ещё» и бесконечная прокрутка** | Повторы и пропуски при подгрузке, нельзя вернуться к месту |
| **Таблица** | Длинные и пустые значения ломают колонки |
| **Выпадающий список** | Нет нужного значения или неверное значение по умолчанию |
| **Чекбоксы и радиокнопки** | «Выбрать все» врёт, подпись не кликается |
| **Выбор даты** | Ручной ввод и календарь ведут себя по-разному; 29 февраля и конец месяца |
| **Загрузка файлов** | Принимает не тот формат или размер, падает на «странном» имени |
| **Скачивание и экспорт** | Кириллица в Excel превращается в кракозябры; экспорт не учитывает фильтр |
| **Модальное окно** | Закрылось случайно и стёрло введённое |
| **Уведомление (тост)** | Исчезает раньше, чем успеваешь прочитать; закрывает кнопки |
| **Подтверждение опасного действия** | «Отмена» всё равно удаляет; текст не говорит, **что** удаляем |

Дальше — по каждому элементу. Структура одинаковая: **что это → что проверять → типичные баги → лайфхак**. Не нужно учить наизусть — это справочник, к нему возвращаются.

## Поиск

**Что это.** Поле, куда пользователь вписывает слово, а система показывает то, что подходит. Бывает поиск по одному полю (названию) или по нескольким (имя, email, телефон).

**Что проверять:**

- **точное совпадение** — `Отчёт` находит «Отчёт»;
- **часть слова** — `чёт` находит «Отчёт»? Начало слова, середина, конец. По требованию: ищет ли поиск подстроку или только с начала;
- **регистр** — `отчёт`, `ОТЧЁТ`, `оТЧЁт` — обычно результат одинаковый. Проверь и латиницу, и кириллицу: они ломаются по-разному;
- **пробелы** — ` отчёт ` с пробелами по краям, только пробелы `   `, двойной пробел внутри;
- **ё и е** — найдётся ли «Ёлка» по запросу «елка». Это вопрос к требованиям, но спросить надо;
- **спецсимволы** — `%`, `_`, `'`, `"`, `\`. Символы `%` и `_` в базе данных означают «любые символы» — поиск по `%` может вернуть **всё**;
- **«ничего не найдено»** — понятный текст, а не пустая таблица или вечная загрузка ([урок 4](/web/04-sostoyaniya-interfeysa), раздел «Пусто»);
- **поиск + фильтр** — работают вместе: искать «отчёт» среди задач «В работе», а не среди всех;
- **очистка** — стёр запрос или нажал крестик → вернулся полный список;
- **сохраняется ли в адресе** — после F5 или «Назад» запрос на месте? Подробно про адрес и состояние — урок 7.

**Типичные баги:**

- поиск чувствителен к регистру — «отчёт» не находит «Отчёт»;
- пробел в конце запроса — «ничего не найдено»;
- запрос `%` возвращает все записи, а `'` — ошибку сервера `500`;
- быстро напечатал слово — результаты «мигают» и в конце показывают результат для **недопечатанного** запроса: ответ на старый запрос пришёл позже ответа на новый.

**Лайфхак.** Открой Network и печатай запрос. Хороший поиск ждёт паузу (это называется **debounce**) и отправляет **один** запрос, а не по запросу на каждую букву. Если запросов столько же, сколько букв, — это нагрузка на сервер и риск «мигающих» результатов.

## Фильтры

**Что это.** Ограничения списка: статус, приоритет, дата, автор. Обычно это выпадающие списки, чекбоксы или кнопки-переключатели над таблицей.

**Что проверять:**

- **каждый фильтр по отдельности** — каждое значение даёт верный набор;
- **комбинации** — два-три фильтра сразу работают как «И»: «В работе» **и** «Высокий». Не нужно перебирать все сочетания — возьми несколько важных пар ([техники тест-дизайна](/osnovy/08-tehniki-test-dizayna) помогут выбрать);
- **пусто после фильтра** — текст «Нет задач по фильтру», а не «Пока нет задач»: данные-то есть, их просто скрыл фильтр;
- **сброс** — есть ли кнопка «Сбросить фильтры» и сбрасывает ли она **все** фильтры, включая поиск;
- **счётчик** — если показано «Найдено: 12» или «12 из 40», число совпадает с тем, что в таблице;
- **фильтр и страница** — сменил фильтр, будучи на 3-й странице: должен вернуться на 1-ю. Иначе увидишь пустую 3-ю страницу из двух;
- **после F5 и «Назад»** — фильтры сохранились или сбросились? Правильного ответа нет, но поведение должно быть описано в требованиях. Нет описания — вопрос аналитику;
- **что видит другой пользователь** — фильтр «Мои задачи» у Ивана и у Анны показывает разное.

**Типичные баги:**

- фильтры работают как «ИЛИ» вместо «И» — результатов больше, чем должно быть;
- после смены фильтра остался на 3-й странице — «ничего не найдено», хотя данные есть;
- «Сбросить» сбрасывает выпадающие списки, но не поиск;
- счётчик считает без учёта фильтра.

**Лайфхак.** Сравнивай с базой. Если есть доступ к БД — один запрос `SELECT COUNT(*) … WHERE status = 'IN_PROGRESS' AND priority = 'HIGH'` сразу говорит, сколько строк должен показать фильтр. Нет базы — Network: посмотри, какие параметры ушли в запросе (`?status=IN_PROGRESS&priority=HIGH`) и сколько пришло в ответе.

## Сортировка

**Что это.** Порядок строк: по названию, дате, приоритету. Обычно — клик по заголовку колонки (стрелка ↑↓) или выпадающий список «Сортировать по».

**Что проверять:**

- **каждая колонка**, по которой обещана сортировка;
- **по возрастанию и по убыванию** — и стрелка в заголовке показывает текущее направление;
- **одинаковые значения** — у пяти задач приоритет «Высокий». Их порядок не должен прыгать при каждом обновлении;
- **пустые значения** — задачи без исполнителя: в начале или в конце? Главное — предсказуемо и одинаково;
- **регистр и алфавит** — «apple» и «Banana», «Ёлка» и «Ель»; латиница и кириллица вместе;
- **числа как числа** — 2, 10, 100, а не 10, 100, 2 (так сортирует строка: сравнивает символы по очереди). То же с датами: `02.01.2025` и `10.12.2024` в виде строк сравниваются неправильно;
- **смысловой порядок** — приоритет «Низкий → Средний → Высокий», а не по алфавиту «Высокий, Низкий, Средний»;
- **все данные, а не страница** — главная проверка. О ней — схема ниже;
- **сортировка + фильтр + поиск** — работают вместе.

**Типичные баги:**

- сортируется только текущая страница;
- числа и даты сортируются как текст;
- приоритеты и статусы — по алфавиту, а не по смыслу;
- строки с одинаковым значением меняются местами при каждом обновлении — и между страницами появляются **дубли и пропуски** (об этом — в разделе «Пагинация»).

Почему такое бывает: на странице 20 строк, разработчик отсортировал их прямо в браузере — быстро и без запроса на сервер. Пока данных меньше одной страницы, всё выглядит идеально. Баг появляется только на **второй** странице, а тестовые данные часто помещаются в одну.

**Лайфхак.** Создай элемент, который **точно** должен оказаться первым при сортировке: название `ААА тест` (или `000 тест`), самая старая дата. Включи сортировку. Если он не на первой строке первой страницы — сортировка не по всем данным.

## Пагинация

**Что это.** Разбивка длинного списка на страницы: «1 2 3 … 10», «Назад / Вперёд», «21–40 из 357». Сервер отдаёт не всё сразу, а кусок: «дай 20 штук, пропусти первые 40».

**Что проверять:**

- **первая страница** — «Назад» неактивна или скрыта;
- **последняя страница** — «Вперёд» неактивна; на ней может быть меньше строк, чем на других, это нормально;
- **граница** — ровно 20 элементов при 20 на страницу: не должно появиться пустой второй страницы. 21 элемент — вторая страница с одной строкой;
- **счётчик** — «21–40 из 357» совпадает с реальностью, в том числе на последней странице;
- **размер страницы** — если можно выбрать 10 / 20 / 50: меняется количество строк, страница возвращается на первую;
- **удаление** — удалил элемент на странице 2: список подтянулся, счётчик уменьшился. Удалил **последний** элемент на последней странице — что видно? Не должно остаться пустой страницы без выхода;
- **добавление** — создал новый элемент, будучи на странице 3: где он появился и не сломался ли счётчик;
- **номер страницы в адресе** — если он есть (`?page=5`), впиши руками `?page=999`, `?page=0`, `?page=-1`, `?page=abc`. Хорошо — пустая страница с понятным текстом или переход на первую. Плохо — ошибка `500` или белый экран;
- **сортировка + пагинация** — пролистай все страницы: ни одна строка не повторилась и ни одна не пропала.

**Типичные баги:**

- **дубли и пропуски.** Две задачи с одинаковым приоритетом стоят на границе страниц. Сервер при каждом запросе ставит их в случайном порядке — одна появляется и на 1-й, и на 2-й странице, а другая не появляется нигде. Лечится вторым ключом сортировки (обычно `id`): «по приоритету, а при равенстве — по номеру»;
- пустая страница после удаления последнего элемента, а кнопки «Назад» нет;
- счётчик на последней странице показывает «41–60 из 45»;
- кто-то добавил запись, пока ты листаешь, — на следующей странице повторилась строка с предыдущей. Это особенность пагинации «пропусти N», а не всегда баг, но про неё стоит знать и спросить, критично ли это.

**Лайфхак.** Для проверки пагинации нужно много данных. Не создавай 50 записей руками — это делается за минуту через Postman Runner (см. «Лайфхаки» ниже). А дубли и пропуски проще ловить в ответах сервера: в Network открой ответы двух соседних страниц и сравни `id` — каждый должен встретиться один раз.

## «Показать ещё» и бесконечная прокрутка

**Что это.** Вместо страниц — кнопка «Показать ещё» или подгрузка, когда долистал до конца (лента соцсети, каталог магазина).

**Что проверять** — коротко, всё остальное как у пагинации:

- новые элементы **добавляются** к старым, а не заменяют их; без дублей на стыке;
- в конце списка — понятный финал: кнопка исчезает или «Больше ничего нет», а не вечный спиннер;
- быстрая прокрутка не отправляет 10 одинаковых запросов (смотри Network);
- ушёл в карточку товара и нажал «Назад» — вернулся на то же место или в самый верх, и всё, что подгрузил, пропало? Для каталога на 500 товаров это серьёзная проблема удобства;
- футер внизу страницы вообще досягаем — при бесконечной прокрутке до него часто невозможно добраться.

## Таблицы

**Что это.** Данные в строках и колонках: список задач, пользователей, заказов.

**Что проверять:**

- **длинные значения** — название из 100 символов, слово без пробелов, email на 60 символов. Перенос, многоточие или вылезает за ячейку? Если многоточие — можно ли увидеть полный текст (подсказка при наведении, карточка). Подробно — [урок 3](/web/03-verstka-i-maket), раздел «Длинный текст»;
- **пустые ячейки** — пусто, «—» или `null` / `undefined`? Одинаково во всей таблице;
- **числа** — выровнены по правому краю, с разделителями разрядов, одинаковое число знаков после запятой: `1 250,00` и `90,50`, а не `1250` и `90.5`;
- **шапка при прокрутке** — у длинной таблицы шапка «прилипает» сверху? Если нет — через 50 строк непонятно, где какая колонка. Это вопрос к макету;
- **широкая таблица на узком экране** — колонки обрезаны или появляется горизонтальная прокрутка;
- **клик по строке** — открывает карточку? А клик по кнопке «Удалить» в строке — не открывает ли заодно и карточку;
- **выделение и действия со строками** — если можно выбрать несколько строк и удалить разом.

**Типичные баги:** длинное название раздвигает таблицу, и колонка «Действия» уезжает за край экрана; `null` в ячейке; клик по кнопке в строке срабатывает дважды — и кнопка, и переход в карточку.

## Выпадающие списки (select)

**Что это.** Поле, где выбирают одно значение из готового списка: статус, страна, роль.

**Что проверять:**

- **все значения на месте** — сверь со спецификацией: нет лишних и не пропущены нужные;
- **порядок** — логичный: по алфавиту, по смыслу (Низкий → Средний → Высокий) или по частоте; не случайный;
- **значение по умолчанию** — какое выбрано при открытии формы. «Выберите…» как заглушка не должно сохраняться как значение;
- **длинные опции** — не обрезаются так, что две разные выглядят одинаково («Отдел разработки моби…» и «Отдел разработки моби…»);
- **поиск внутри** — если список длинный (страны, пользователи): ищет по части слова, по-русски и по-английски;
- **клавиатура** — стрелки, Enter, первая буква перескакивает к нужному пункту;
- **сохранение** — выбрал, сохранил, открыл снова — выбрано то же самое.

**Типичные баги:** по умолчанию выбрано первое значение, и человек сохраняет его, не заметив; в списке осталось значение, которое бэк уже не принимает; список не помещается в окно и обрезается краем модалки.

## Чекбоксы и радиокнопки

**Что это.** Чекбокс (квадратик) — «да / нет», можно выбрать несколько. Радиокнопки (кружки) — ровно один вариант из группы.

**Что проверять:**

- **клик по подписи** — нажатие на текст рядом тоже ставит галочку. Маленький квадратик трудно попасть мышкой и пальцем;
- **радио — только одно** — выбрал второй вариант, первый снялся. Есть ли вариант по умолчанию;
- **«Выбрать все»** — ставит все галочки; снял одну — «Выбрать все» стала «частично» (минус в квадратике) или снялась; поставил все вручную — «Выбрать все» включилась сама;
- **«Выбрать все» и пагинация** — выбирает всё на странице или все 357 записей? Это нужно знать до нажатия «Удалить выбранные»;
- **клавиатура** — Tab до чекбокса и пробел ставят галочку;
- **сохранение** — после сохранения и F5 галочки на месте.

**Типичные баги:** подпись не кликается; «Выбрать все» выбирает только видимую страницу, а кнопка пишет «Удалить 357»; галочка стоит, но в запрос уходит `false`.

## Выбор даты

**Что это.** Поле даты с календарём. Часто его можно заполнить двумя способами: выбрать в календаре или вписать руками.

**Что проверять:**

- **ручной ввод и календарь** — оба способа дают одинаковый результат; вписанная руками дата отображается в календаре;
- **формат** — `05.03.2025` — это 5 марта или 3 мая? Что будет, если вписать в другом формате;
- **границы** — минимальная и максимальная дата по требованию. Нельзя выбрать дату рождения в будущем или срок в прошлом;
- **прошедшие даты** — если «срок» не может быть в прошлом, вчерашняя дата недоступна, а сегодняшняя доступна;
- **несуществующие даты** — `31.04`, `30.02`, `29.02` в невисокосный год (2025) и в високосный (2024);
- **конец месяца** — «+1 месяц» от 31 января — это 28 (29) февраля или 3 марта;
- **диапазон** «с … по …» — «с» позже «по» должно давать ошибку или меняться местами; один и тот же день в обоих полях — допустим;
- **очистка** — можно ли стереть дату в необязательном поле;
- **что ушло на сервер** — в Network → Payload: `2025-03-05` или что-то неожиданное, со сдвигом на день.

**Типичные баги:** руками можно вписать дату, которую календарь не даёт выбрать; `31.04` превращается в `01.05` без предупреждения; дата сохранилась на день раньше. Последнее — почти всегда часовые пояса, им посвящён урок 12.

**Лайфхак.** В календаре проверь **переход года**: 31 декабря → «следующий месяц» → январь **следующего** года, а не того же.

## Загрузка файлов

**Что это.** Кнопка «Выбрать файл», зона «Перетащите файл сюда», аватар, вложение к задаче.

**Что проверять:**

- **разрешённые форматы** — каждый из списка загружается; запрещённый — понятная ошибка с перечнем допустимых;
- **расширение и содержимое** — файл `photo.jpg.exe` (двойное расширение) или текстовый файл, переименованный в `.jpg`. Проверку должен делать **сервер**, а не только окно выбора файла;
- **размер** — ровно максимум, чуть больше максимума, очень большой (пусть сервер откажет быстро, а не после 10 минут загрузки);
- **пустой файл, 0 байт** — понятная ошибка, а не «загружено» пустое вложение;
- **имя файла** — длинное (200 символов), кириллическое `Отчёт за март.pdf`, с пробелами и спецсимволами `отчёт (1) №2.pdf`. Сохраняется ли имя без искажений и скачивается ли файл потом с тем же именем;
- **перетаскивание** — работает так же, как кнопка; что будет, если перетащить папку или 5 файлов, когда можно один;
- **несколько файлов** — лимит количества; один из пяти плохой — что с остальными;
- **прогресс и отмена** — большой файл показывает прогресс; можно отменить; после отмены ничего не загрузилось;
- **сеть оборвалась** — загрузка на медленной сети с Throttling, а потом **Offline**: понятная ошибка, можно повторить;
- **повторная загрузка** — тот же файл ещё раз: заменился, добавился вторым или ошибка — как в требовании.

**Типичные баги:** окно выбора показывает только `.jpg`, но через перетаскивание проходит любой файл; кириллическое имя превращается в `%D0%9E%D1%82…` или `????.pdf`; файл в 0 байт «загружен»; большой файл грузится минуту, а потом «Ошибка» без объяснений.

::: warning Только безобидные файлы
Для проверки «опасного» расширения достаточно **переименовать обычный текстовый файл** в `photo.jpg.exe`. Никаких настоящих программ, вирусов и «тестовых вредоносных» файлов из интернета — ни на учебных сайтах, ни на работе без отдельного разрешения.
:::

## Скачивание и экспорт

**Что это.** «Скачать», «Экспорт в Excel / CSV», «Выгрузить отчёт в PDF».

**Что проверять:**

- **имя файла** — понятное (`задачи_2025-03-05.csv`, а не `download` или `export (7)`), без недопустимых символов;
- **содержимое** — совпадает с тем, что на экране: те же строки и колонки, без лишних служебных полей вроде `id` или `deleted`;
- **экспорт с фильтром** — выгрузились только отфильтрованные строки или все? Как должно быть — в требовании. Если «все», а человек ждал отфильтрованные, это вопрос аналитику;
- **все страницы** — экспорт берёт все 357 строк, а не 20 с текущей страницы;
- **пустой экспорт** — когда по фильтру ничего нет: пустой файл с заголовками, сообщение «Нечего выгружать» или ошибка?
- **кириллица** — открой CSV **двойным кликом в Excel**. Именно так сделает пользователь;
- **числа и даты** в Excel — `0012` не превратилось в `12`, длинный номер — в `1,23E+15`, дата — в число;
- **большой экспорт** — 10 000 строк не вешает страницу; если готовится долго — есть индикатор.

**Типичные баги:** кириллица в Excel — кракозябры; экспорт выгружает только текущую страницу; запятая в названии разрывает строку CSV на две колонки.

**Лайфхак — кракозябры в CSV.** CSV — простой текст. Excel при двойном клике часто не понимает, что текст в кодировке UTF-8, и показывает кириллицу кракозябрами. Сам файл при этом обычно правильный — открой его в текстовом редакторе, и всё будет читаемо. Как проверить, кто виноват:

1. Открой файл в текстовом редакторе (VS Code, «Блокнот», TextEdit). Кириллица нормальная — файл в порядке.
2. В Excel: **Данные → Из текстового / CSV-файла** → выбери кодировку **UTF-8**. Если так читается — проблема в том, как файл открывается двойным кликом.
3. Это всё равно баг для пользователя: он не знает про кодировки. Обычно его решают специальной меткой в начале файла (её называют **BOM**) — разработчик поймёт, о чём речь.

## Модальные окна

**Что это.** Окно поверх страницы: «Новая задача», «Удалить?», «Добавить участника». Страница за ним затемнена и недоступна.

**Что проверять:**

- **все способы закрыть** — крестик, кнопка «Отмена», клавиша **Esc**, клик по затемнённому фону. Какие из них должны работать — по требованию. Главное — они ведут себя одинаково во всех окнах сайта;
- **несохранённые данные** — заполнил форму в окне, закрыл случайно (Esc, клик мимо): данные пропали молча, спросило «Закрыть без сохранения?» или сохранилось как черновик. Для длинной формы молчаливая потеря — серьёзная проблема удобства;
- **открыл снова** — окно чистое или с данными прошлого раза; не висят старые ошибки ([урок 5](/web/05-formy-i-validaciya), раздел «Отправка формы»);
- **фокус** — при открытии курсор встаёт в первое поле; **Tab** ходит по полям **внутри** окна и не уходит на страницу за ним; после закрытия фокус возвращается на кнопку, которая открыла окно. Это важно для тех, кто работает с клавиатуры, — подробно в уроке 13 «Доступность»;
- **прокрутка фона** — крутишь колёсико над окном: прокручивается окно или страница за ним?
- **длинное содержимое** — окно выше экрана: прокручивается внутри, кнопки «Сохранить» и «Отмена» достижимы;
- **окно поверх окна** — из окна «Задача» открыли «Удалить комментарий?». Esc закрывает только верхнее? Клик мимо не закрывает оба сразу?
- **узкий экран** — окно помещается, крестик виден.

**Типичные баги:** клик мимо стирает заполненную форму; одно Esc закрывает оба окна; после закрытия окна страница не прокручивается (осталась «заблокированной»); кнопка «Сохранить» за нижним краем экрана.

**Лайфхак.** Клик «мимо» часто происходит не специально: человек выделяет текст в поле мышкой и отпускает кнопку **за краем** окна. Проверь именно так — зажми мышь внутри поля, протяни за край окна и отпусти. Окно закрылось — данные пропали на ровном месте.

## Уведомления (тосты)

**Что это.** Короткое сообщение, которое всплывает в углу и само исчезает: «Задача создана», «Не удалось сохранить». Называют «тост» — выскакивает, как хлеб из тостера.

**Что проверять:**

- **текст** — понятный, по делу: «Задача создана», а не «Success» или «OK»;
- **тип** — успех, ошибка, информация отличаются цветом **и** значком, не только цветом;
- **время показа** — успеваешь прочитать? Короткое «Сохранено» может исчезнуть через 3–5 секунд; длинную ошибку за это время не прочитать. Ошибку часто оставляют висеть, пока не закроешь;
- **закрытие** — есть крестик; уведомление закрывается и само;
- **несколько сразу** — сделай 5 действий подряд: уведомления встают стопкой, не наползают друг на друга, не заполняют весь экран;
- **что под ним** — уведомление не закрывает важные кнопки (меню, «Выйти», «Сохранить»). Пока оно висит, можно ли нажать то, что под ним;
- **не дублирует** — одна ошибка показана в одном месте, а не и баннером в форме, и тостом ([урок 5](/web/05-formy-i-validaciya));
- **уход со страницы** — показал уведомление и сразу перешёл на другую страницу — оно не потерялось и не «застряло».

**Типичные баги:** ошибка исчезает раньше, чем её успели прочитать или сфотографировать для баг-репорта; стопка уведомлений закрывает кнопку «Выйти»; при быстрых действиях одно и то же уведомление показывается трижды.

**Лайфхак.** Тост исчез, а текст нужен для баг-репорта? Смотри ответ в Network — текст ошибки обычно там, в `message`. А чтобы спокойно рассмотреть сам тост, запиши экран видео.

## Подтверждение опасных действий

**Что это.** Вопрос перед необратимым: «Удалить проект?», «Точно?», «Сбросить все настройки?». Бывает отдельным окном или прямо на кнопке: «Удалить» → «Точно удалить?» + «Отмена».

**Что проверять:**

- **«Отмена» действительно отменяет** — после неё ничего не удалилось; проверь F5 и Network: не ушёл ли запрос `DELETE`;
- **все способы закрыть окно подтверждения** — Esc, крестик, клик мимо — тоже отмена, а не согласие;
- **текст говорит, ЧТО удаляем** — «Удалить задачу «Отчёт за март»?», а не просто «Вы уверены?». Человек мог открыть подтверждение не у той строки;
- **последствия** — сказано, что будет с вложенным: «задачи проекта тоже удалятся», «действие нельзя отменить»;
- **опасная кнопка выделена** — красная, с понятной надписью «Удалить», а не «ОК»; по умолчанию фокус **не** на ней — случайный Enter не должен удалять;
- **двойной клик по «Удалить»** — один запрос, а не два (второй вернёт ошибку «не найдено» и напугает пользователя);
- **после удаления** — понятный итог: уведомление, элемент исчез из списка, счётчик уменьшился;
- **ошибка при удалении** — нет прав, сервер отказал: понятный текст, элемент остался на месте.

**Типичные баги:** «Отмена» закрывает окно, но запрос `DELETE` уже ушёл; подтверждение без названия объекта; Enter сразу после открытия окна удаляет; удалили — элемент висит в списке до F5.

## Лайфхаки

### Папка «test-files» — один раз на всю жизнь

Заведи папку `test-files` и сложи туда файлы для проверки загрузки. Когда в задаче появится «загрузка вложений», не придётся искать подходящий файл по всему компьютеру.

| Файл | Зачем |
|---|---|
| `empty.txt` — 0 байт | Пустой файл |
| `small.jpg`, `small.png`, `small.pdf`, `small.docx` | По одному каждого популярного формата |
| `big-50mb.bin`, `big-200mb.bin` | Больше типичных ограничений |
| `photo.jpg.exe` — переименованный текстовый файл | Двойное расширение |
| `fake.jpg` — текстовый файл с расширением `.jpg` | Расширение не совпадает с содержимым |
| `Отчёт за март (финал) №2.pdf` | Кириллица, пробелы, скобки, спецсимволы |
| `aaaa…aaa.txt` — имя на 200 символов | Длинное имя |
| `photo.JPG` | Расширение заглавными буквами — часто не проходит проверку `.jpg` |
| `huge-image.jpg` — фото 8000×6000 | Большая картинка: как её покажет предпросмотр |

### Большой файл одной командой

Не ищи «какой-нибудь фильм на 200 МБ». Файл нужного размера создаётся одной командой в терминале. Внутри — нули, он безопасен.

**macOS** (Терминал):

```bash
mkfile 50m big-50mb.bin
mkfile 200m big-200mb.bin
touch empty.txt
```

`mkfile` принимает размер с буквой: `k` — килобайты, `m` — мегабайты, `g` — гигабайты. `touch` создаёт пустой файл в 0 байт.

**Windows** (PowerShell или командная строка):

```powershell
fsutil file createnew big-50mb.bin 52428800
fsutil file createnew big-200mb.bin 209715200
fsutil file createnew empty.txt 0
```

У `fsutil` размер — **в байтах**: 50 МБ = 50 × 1024 × 1024 = 52 428 800. Если Windows пишет, что не хватает прав, — запусти терминал от имени администратора.

Нужен файл «ровно максимум» и «максимум + 1 байт»? Например, лимит 10 МБ — это `10485760` байт. На macOS размер без буквы — в байтах: `mkfile 10485760 limit.bin` и `mkfile 10485761 limit-plus-1.bin`. На Windows — те же числа в `fsutil file createnew`. Осторожно: буква `b` у `mkfile` — это не байты, а блоки по 512 байт.

### Много данных для пагинации — за минуту

Чтобы проверить пагинацию, нужно больше записей, чем помещается на страницу. Создавать 50 штук руками — полчаса. Через Postman — минута:

1. Создай одну запись через интерфейс, в Network найди запрос `POST` → **Copy as cURL (bash)** → в Postman **Import**.
2. Сохрани запрос в коллекцию (Runner запускает только сохранённые запросы).
3. Коллекция → **Run** → **Iterations: 25** → **Run**. Запрос выполнится 25 раз — 25 новых записей.
4. Хочешь разные названия — поставь в тело динамическую переменную <span v-pre>`{{$randomWord}}`</span>: в каждой итерации Postman подставит новое случайное слово.

Подробно про Runner, итерации и файлы данных — в уроке [«Postman и curl»](/api/10-postman-i-curl), раздел «Runner и data-driven».

::: tip Одинаковые названия — тоже проверка
Создай 25 записей с **одинаковым** названием и включи сортировку по названию. Так ты сразу проверишь «одинаковые значения»: при листании страниц ни одна запись не должна повториться или пропасть.
:::

## Как работать на задаче — по шагам

**Шаг 1. Увидел элемент в задаче.** «Добавить фильтр по исполнителю в список задач». Элементы здесь — фильтр (новый) и всё, с чем он соседствует: поиск, сортировка, пагинация, пустое состояние.

**Шаг 2. Взял чек-лист.** Скопировал из своих заметок чек-лист «Фильтры» и пункты «фильтр + пагинация», «фильтр + поиск».

**Шаг 3. Вычеркнул неприменимое.** Счётчика «Найдено: N» на экране нет — пункт про счётчик убрал. Сохранение в адресе — не входит в задачу, но **спросил** аналитика: «Фильтр сбрасывается после F5 — так задумано?»

**Шаг 4. Добавил специфику из спецификации.** «Исполнитель» — поиск по всем пользователям, есть вариант «Без исполнителя». Значит, добавляю: фильтр «Без исполнителя», исполнитель, у которого нет задач, удалённый пользователь.

**Шаг 5. Подготовил данные.** Для пагинации — 25 задач через Postman Runner. Для пустых значений — задачи без исполнителя. Для «одинаковых» — несколько задач у одного человека на границе страниц.

**Шаг 6. Прошёл.** По каждому пункту — результат: ок / баг / вопрос. Network открыт всё время: какие параметры ушли, что пришло.

**Шаг 7. Заведи баги и обнови свой чек-лист.** Нашёл новый вид бага — допиши пункт в чек-лист. Через полгода у тебя будет справочник лучше любого из интернета, заточенный под твой проект.

::: tip Чек-лист — живой документ
Чек-листы из этого урока — стартовые. Храни их в одном месте (заметки, Confluence, Google-документ) и дополняй после каждого найденного бага. Это и есть опыт, записанный на бумагу.
:::

Какие типовые элементы есть в TaskFlow:

| Элемент | Где |
|---|---|
| **Поиск** | Поиск задач по названию — на странице проекта и в «Мои задачи»; поиск пользователя в окнах «Добавить участника» и «Новая задача» (поле «Исполнитель») |

| **Пагинация** | «Назад / Вперёд» и «X–Y из N» — «Мои проекты», задачи проекта, «Мои задачи», «Администрирование → Пользователи». По 20 на страницу |
| **Таблицы** | Все списки выше и участники проекта |
| **Выпадающие списки** | Фильтры; статус задачи прямо в строке таблицы; приоритет в окне задачи; роль участника |
| **Кнопки-переключатели** | Метки в окне задачи — нажал чип, он выделился |
| **Модальные окна** | «Новый проект», «Новая задача» / «Изменить задачу», «Добавить участника», карточка задачи, подтверждения удаления |
| **Уведомления** | «Задача создана», «Статус обновлён», ошибки действий — в правом верхнем углу |
| **Подтверждение опасных действий** | Окно «Удалить задачу?», «Удалить проект?», «Удалить участника?»; «Удалить» → «Точно?» у комментария; «Точно удалить?» у метки; «Сбросить БД» |

Чего в TaskFlow **нет**: сортировки в интерфейсе, выбора даты, загрузки и скачивания файлов, «Показать ещё». Сортировку можно проверить через API: у `GET /api/v1/tasks` есть параметры `sort` и `order` (`docs/API_SPEC.md`, раздел 6.4). Остальное — на учебных сайтах.

## Разборы из жизни

Три случая с разных проектов. Первый открыт — это образец.

<details class="details custom-block" open>
<summary>Разбор 1. «Самый дорогой товар — на третьей странице»</summary>

**Ситуация.** Интернет-магазин электроники. В каталоге добавили сортировку «Сначала дорогие». Тестировщик проверил на стенде: 15 товаров, одна страница, всё по убыванию цены — задачу закрыли. Через неделю после выкладки маркетолог пишет: «Сортирую ноутбуки по цене, на первой странице — от 90 до 40 тысяч, а самый дорогой, за 250, — на третьей».

**Что видит мидл.**

- На стенде товаров было меньше одной страницы. Сортировку **всех данных** и сортировку **текущей страницы** на таком наборе не отличить.
- Фронт получал от сервера страницу из 24 товаров в порядке добавления и сортировал их в браузере. Каждая страница по отдельности выглядела правильно.
- В требованиях было «сортировка по цене», без слов «по всему каталогу», — но пользователь иначе её и не понимает.

**Что делать.**

1. Воспроизвести: товаров больше одной страницы, сортировка «Сначала дорогие». Сравнить последнюю цену на странице 1 и первую на странице 2.
2. В Network убедиться: в запросе нет параметра сортировки (`sort=price`), сервер отдаёт всё в старом порядке.
3. Завести баг с высоким приоритетом: пользователь видит неверные данные, а маркетинговые подборки «самые дорогие / самые дешёвые» врут.
4. Себе в чек-лист сортировки: «данных больше одной страницы» и «эталонный элемент, который точно должен быть первым».

**Чего не делать.**

- Не проверять сортировку и пагинацию на данных, которые помещаются на одну страницу.

</details>

::: details Разбор 2. Экспорт для бухгалтерии: «Файл битый»
**Ситуация.** Система учёта заказов. Добавили кнопку «Экспорт в CSV». Тестировщик скачал файл, открыл в редакторе кода — все колонки, кириллица на месте. Задачу закрыли. Через день бухгалтер: «Ваш файл битый, там иероглифы».

**Что видит мидл.**

- Бухгалтер открывает CSV двойным кликом в Excel. Excel не понял, что файл в UTF-8, и прочитал кириллицу в другой кодировке — получились кракозябры.
- Сам файл правильный — в редакторе всё видно. Но пользователь не открывает файлы в редакторе кода.
- Заодно: в колонке «Номер заказа» `000123` превратилось в `123`, а сумма `1250.50` в русском Excel стала датой или текстом.

**Что делать.**

1. Повторить путь пользователя: скачать и открыть **двойным кликом в Excel** — на Windows и на macOS, если есть.
2. Завести баг: «CSV-экспорт: кириллица в Excel отображается некорректно при открытии двойным кликом». Приложить скриншот Excel и тот же файл в редакторе — для сравнения.
3. Отдельно — вопрос про номера с ведущими нулями и формат сумм: как их ждёт бухгалтерия.

**Чего не делать.**

- Не проверять экспорт только в «удобной» для тестировщика программе. Проверяй тем, чем пользуется пользователь.
:::

::: details Разбор 3. «Клик мимо — и полчаса работы пропали»
**Ситуация.** CRM для менеджеров по продажам. Карточка сделки открывается во всплывающем окне: 20 полей, комментарий на полстраницы. Менеджеры жалуются: «Заполняю сделку, а она вдруг исчезает, всё пропало».

**Что видит мидл.**

- Окно закрывается кликом по затемнённому фону. Менеджер выделяет текст в комментарии мышкой, ведёт курсор чуть дальше края окна и отпускает — браузер считает это кликом по фону.
- Окно закрывается **без вопроса** «Закрыть без сохранения?». Данные не сохранены никуда.
- Тестировщик проверял «закрывается ли окно по клику мимо» — да, закрывается. Проверка формально пройдена, а проблему никто не увидел.

**Что делать.**

1. Воспроизвести: заполнить поле, выделить текст мышкой с отпусканием за краем окна. Видео — лучшее доказательство.
2. Завести баг высокого приоритета: потеря введённых данных.
3. Предложить варианты дизайнеру: не закрывать окно с несохранёнными данными по клику мимо, спрашивать подтверждение или сохранять черновик.
4. Проверить остальные окна с формами — они обычно сделаны одним компонентом.

**Чего не делать.**

- Не ограничиваться «способ закрытия работает». Спрашивай: **что станет с данными**, когда окно закроется случайно?
:::

## Частые ошибки

- **Проверять сортировку и пагинацию на одной странице данных.** Нужно больше записей, чем помещается на страницу, — Postman Runner делает их за минуту.
- **Проверять поиск только «чистыми» словами.** Регистр, пробелы, часть слова, `%` — обязательные пункты.
- **Проверять фильтры по одному.** Баги живут в комбинациях и в связке «фильтр + страница».
- **Проверять экспорт в редакторе, а не в Excel.** Пользователь откроет двойным кликом.
- **Загружать только «правильные» файлы.** Пустой, большой, с кириллицей в имени, с чужим расширением — папка `test-files` под рукой.
- **«Окно закрывается — ок».** Важнее, что стало с данными, куда ушёл фокус и не закрылось ли окно под ним.
- **Не нажимать «Отмена».** В подтверждении удаления «Отмена» — такая же проверка, как «Удалить». И смотри Network: не ушёл ли `DELETE`.
- **Проходить чек-лист целиком, не думая.** Сначала вычеркни неприменимое и добавь специфику задачи — иначе час уйдёт на проверки, которые не нужны.
